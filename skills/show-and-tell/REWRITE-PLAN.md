# Plan: UI rewrite to Material 3 Expressive (Lit + @m3e/web, TypeScript)

Status: started. Step 1 is done. Work through the steps in order and commit each step separately. The
existing checks (`node tests/run.mjs`) describe the old UI and need not pass during the rewrite; new
ones are written after it (step 7). The rules that hold throughout are in `AGENTS.md`.

## Why

- Google's Material Web (`@material/web`, used today) is in maintenance mode and will not get
  M3 Expressive ("Material 3 Expressive is not implemented on Web", m3.material.io/develop/web).
- `@m3e/web` (github.com/matraic/m3e, MIT, Lit 3 based) implements M3 Expressive, including
  `m3e-split-button`, `m3e-menu`, `m3e-theme` (expressive motion), and SVG icons via `@m3e/icons`.
  Risk: a single maintainer.

## Decisions

| Topic | Decision |
|---|---|
| Component library | `@m3e/web` + `@m3e/icons` (SVG icons, no icon font download) |
| Framework | Lit everywhere, not React (`@m3e/web` is Lit already; no second runtime) |
| Language | TypeScript, built with esbuild; `tsc --noEmit` for type checks |
| Font | System font (`system-ui, "Segoe UI", sans-serif`), no bundled Roboto Flex |
| Colours | "Warm paper and ink": surfaces and containers are tonal spot from the seed `#8A6A4A`, the primary is black (white in dark) from the monochrome scheme, light + dark, generated by `vendor-src/build.mjs` into `extension/vendor/m3-tokens.css`. The only strong colour is the session's (`--session`, the tab group's colour): app icon in the panel header, icons next to agent messages, status dot. `m3e-theme` is used for motion and shape only, not for colour generation |
| Structure | Strict atomic design (see below) |
| Built output | Committed in `extension/ui/`, like `extension/vendor/` today; the extension runs without a build step |
| Design | The canvas "Show and Tell — M3E Redesign" is the reference for every screen and state |
| Icons | `@m3e/icons`, one import per icon. The app icon (`icons/icon.svg`) is the one own drawing |
| Chat input | A custom 28px pill with a borderless field; the buttons inside are stock M3E |

## Scope per part

| Part | Files today | Target |
|---|---|---|
| Side panel | `extension/panel.html`, `panel.js`, `panel.css` | Lit + `@m3e/web`, atomic design |
| Small extension pages | `tab.html`, `open-panel.html`, `lab-offline.html` | Lit + `@m3e/web` |
| Overlay (content script) | `extension/content.js` | `lit-html` templates only, rendered into the existing closed shadow root; atomic design as template functions; own controls (annotation toolbar, note editor) styled with the same M3 Expressive tokens |
| Video stage (content script) | `extension/stage.js` | Same as the overlay |
| Demo page | `scripts/lab.mjs` (+ `scripts/lab-vendor/`) | Lit + `@m3e/web`, separate from the extension; element ids stay (checks and README use them) |

Not in scope: `service-worker.js`, `pause.js`, `bridge/`, behaviour in general. Same features, same
messages between panel and worker.

### The one exception: content scripts

Content scripts run in Chrome's isolated world, where `customElements` is `null` (checked on Chrome 156;
Chromium issue 41118431). So no `LitElement` and no `@m3e/web` there, only `lit-html`'s `render()`.
`lit-html` itself works there (checked). The overlay's per-frame position updates (`frame()`, following
elements while the page scrolls) stay direct style writes, not re-renders.

## Atomic design rules (to go into an AGENTS.md in this folder as step 1)

- Levels: **atoms** (`@m3e/web` elements, plus own ones such as status dot, avatar), **molecules**
  (e.g. listen status, attachment chip), **organisms** (app bar, pause card, throttle card, notice,
  composer, conversation), **templates** (panel layout), **pages** (panel, small pages, demo page).
- Imports only point downward. No organism imports another organism's internals.
- Only pages touch `chrome.*`, storage and messaging. Everything below takes properties and fires
  typed `CustomEvent`s (`bubbles: true, composed: true`).
- Styling: tokens only (`--md-sys-*`), no literal colours or radii in components.
- Panel and demo page share tokens and nothing else.
- In content scripts the levels are template functions (`atoms/callout.ts` returning `html\`...\``), same
  downward-only rule.

## Spike results (done, in `%TEMP%\sat-spike`, throwaway)

- Pause card as a Lit organism with `m3e-split-button` + `m3e-menu`: works on an extension page, no CSP
  or console errors, real click opens the menu, choosing an item fires the event.
- Bundle: pause card alone 433 KB (87 KB gzip); about 180 KB is the fixed base (`theme`, `core`).
  Expect about 600 KB for the full panel; loaded from disk, acceptable.
- TypeScript config that worked: `experimentalDecorators: true`, `useDefineForClassFields: false`,
  `moduleResolution: bundler`, `strict: true`.
- `m3e-split-button` replaces the hand-built split button in `panel.css` (`.split`, `--split-inner`).

## Steps

1. **Done.** AGENTS.md in this folder (rules above), source folder `ui-src/` (already excluded by
   `tests/run.mjs`), `package.json`, `tsconfig.json`, esbuild build writing into `extension/ui/`.
   `vendor-src/build.mjs` keeps the colour tokens (`npm run tokens`) and now writes the new palette.
2. Side panel. Update the tests in the same step: they address panel elements by id
   (`#pause`, `#pause-split`, `#pause-menu`, `#listen-text`, `#conn`, ...) and read
   `md-menu`'s shadow DOM; keep ids where possible, adapt selectors where not.
3. Small pages.
4. Overlay and video stage with `lit-html`.
5. Demo page.
6. Remove `@material/web` and the old bundles; update README ("Rebuild the vendored UI library") and
   SKILL.md where they mention the UI.
7. New tests for the new UI, replacing the old checks in `tests/` and `scripts/real-input-check.mjs`.

## Testing

- `node tests/run.mjs` runs everything on a throwaway copy (bridge 47713, CDP 9434, lab 47714, own
  profile); never use the user's running browser. `--keep` reuses the test browser, `--clean` removes it.
- Check light and dark screenshots (`%TEMP%/show-and-tell-test/shots`) at panel width 360 and 320.
- Do not push or reload the extension in the user's running browser without asking.
